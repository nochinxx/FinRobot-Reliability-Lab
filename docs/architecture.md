# FinRobot Reliability Lab — Architecture

> The existing pipeline is a working prototype. This document reflects the architecture as of v0.4 (Jun 2026) and the planned target structure. Quant-validity claims remain preliminary until the backtest and recommendation-capture pipeline are expanded.

## Positioning

This project is an **auditable reliability and model-risk layer for agentic equity research** — not an AI stock picker. The target audience is quant/financial risk/model-risk/AI research infrastructure teams at institutional firms (BlackRock, JPM, BofA).

It sits on top of FinRobot, which generates HTML equity research reports. The lab extracts, verifies, scores, critiques, and backtests those reports.

## Current Architecture (v0.4)

```
INPUT
  finrobot_equity/core/output/{TICKER}_Equity_Research_Report.html
  (Generated by FinRobot using local Ollama Gemma4 12B MLX)

PHASE 1 — Claim Extraction
  reliability_lab/claim_extraction.py
    mode=auto → Claude claude-sonnet-4-6 (LLM extraction) → fallback regex
    mode=regex → deterministic regex over stripped HTML text
  Output: output/{TICKER}/{TICKER}_claims.json

PHASE 2 — Fact Verification
  reliability_lab/fact_table_builder.py
    dispatch per claim → one of:
      reliability_lab/verifiers/sec_verifier.py    [Tier 1: SEC EDGAR XBRL]
      reliability_lab/verifiers/fmp_verifier.py    [Tier 3: FMP free tier]
      reliability_lab/verifiers/price_verifier.py  [Tier 1: yfinance]
  Output: output/{TICKER}/{TICKER}_fact_table.csv

PHASE 3 — Scoring
  reliability_lab/reliability_metrics.py
    Computes: SCR, PSCR, UCR, ICR, valuation_dispersion
  Output: output/{TICKER}/{TICKER}_reliability_scorecard.json

PHASE 4 — Audit Summary
  run_reliability_audit.write_audit_summary()
  Output: output/{TICKER}/{TICKER}_audit_summary.md

PHASE 5 (optional, --critic flag) — Adversarial Review
  reliability_lab/critic_agents.py
    Skeptical Analyst (LLM) → identifies 3-5 weakest claims
    Thesis Synthesizer (LLM) → writes audited investment memo
    LLM: Anthropic claude-sonnet-4-6 first, Ollama fallback
  Output: {TICKER}_critic_findings.json, _thesis_change.md, _audited_memo.md

SEPARATE — Date-Gated Historical Backtest
  run_historical_backtest.py
    FMP date-gated financial data → valuation signal (P/E + EV/EBITDA vs. mean)
    yfinance → forward returns at 3/6/9/12m vs. SPY
  Output: output/historical_backtest/ (snapshots + results.csv + paper_table.md)
```

## Source Hierarchy

| Tier | Source | Used For |
|------|--------|----------|
| 1 | SEC EDGAR XBRL | Revenue, EBITDA proxy (historical reported financials) |
| 1 | Exchange / price feeds (yfinance) | Price, returns, SPY benchmark |
| 2 | Company IR, earnings releases, transcripts | (planned — not yet integrated) |
| 3 | FMP free tier | EPS, P/E, EV/EBITDA, margins, FCF, net income, total debt |
| 4 | News / analyst commentary | (not used for verification) |
| 5 | LLM-generated text (FinRobot) | The object being audited |

**Conflict rule:** Tier 1 wins when sources disagree. Both values are recorded. Delta > tolerance → `SOURCE_CONFLICT` status.

## Target Architecture (PR2+)

The planned module structure separates concerns cleanly:

```
audit/
  ingestion/
    report_loader.py         ← file reading + HTML stripping
    html_table_parser.py     ← structured table extraction (PR2, after PoV review)
  extraction/
    claim_extractor.py       ← from claim_extraction.py
    recommendation_extractor.py
  sources/
    sec_edgar.py             ← from verifiers/sec_verifier.py
    fmp.py                   ← from verifiers/fmp_verifier.py
    yfinance_prices.py       ← from verifiers/price_verifier.py
    source_registry.py       ← maps metric → [source, priority, tolerance]
  verification/
    revenue.py
    growth.py
    margins.py
    valuation_multiples.py
    prices.py
  disagreement/
    run_manager.py           ← run all applicable sources per claim
    master_fact_table.py     ← multi-source merged results
    conflict_resolver.py     ← SOURCE_CONFLICT logic
  critics/
    skeptical_analyst.py
    quant_risk_reviewer.py   ← ICR trends, coverage gaps, source-tier reliability
    model_risk_reviewer.py   ← prompt determinism, fallback behavior
    thesis_synthesizer.py
  scoring/
    metrics.py
    gates.py                 ← configurable pass/fail thresholds
    reliability_scorecard.py
  backtesting/
    date_gated_dataset.py    ← from fmp_verifier.get_historical_financials
    signal_extractor.py      ← from run_historical_backtest.compute_valuation_signal
    returns.py
    performance.py
  outputs/
    annotated_report.py      ← HTML with inline claim annotations
    investment_committee_memo.py
    dashboard_export.py      ← machine-readable JSON for institutional consumers
```

**Migration rule:** During transition, `reliability_lab/` stays intact. New modules live in `audit/` and re-export from old locations via compatibility shims. CLIs are not modified.

## Three Signal Families (tracked separately)

| Signal | Source | CLI |
|--------|--------|-----|
| Valuation-multiple signal | P/E + EV/EBITDA vs. historical mean | `run_historical_backtest.py` |
| Original FinRobot recommendation | Extracted from HTML report | `run_reliability_audit.py` |
| Critic-revised recommendation | Post-adversarial-critique | `run_reliability_audit.py --critic` |

These are tracked independently. Signal family correlation is a future research question — do not connect them before PR3.

## Determinism and Reproducibility

Every LLM call must log (PR2 target, schema defined in PR1):

```json
{
  "run_id": "uuid",
  "timestamp": "ISO8601",
  "ticker": "NVDA",
  "phase": "claim_extraction | adversarial_critic",
  "model_name": "claude-sonnet-4-6",
  "provider": "anthropic | ollama_fallback",
  "temperature": 0.0,
  "prompt_file": "prompts/skeptical_analyst_v1.txt",
  "prompt_hash": "sha256:...",
  "input_hash": "sha256:...",
  "output_hash": "sha256:..."
}
```

Ollama fallback outputs must be labeled separately — do not mix with Anthropic outputs in aggregate statistics.

## Known Issues / Active Artifacts

| Issue | Root Cause | PR Fix |
|-------|-----------|--------|
| High ICR (e.g., NVDA 53%) | Period attribution: `_nearest_year()` assigns wrong year | PR2: fix multi-year sentence detection |
| HTML table linearization | `_strip_html()` discards column/row structure | PR2: inject `html_table_parser.py` after PoV review |
| Prompts are inline strings | Not versioned or inspectable | PR1: extract to `prompts/` |
| Backtesting logic in CLI | `compute_valuation_signal()` not importable | PR2: move to `audit/backtesting/` |
| No conflict detection | Single source wins silently | PR3: `disagreement/` layer |
| Scorecard thresholds hardcoded | `_TARGET_SCR = 0.80` in reliability_metrics.py | PR2: move to `scoring/gates.py` |
