# Source Hierarchy

This document defines the trust tiers for data sources used in verification. When sources conflict, higher tiers take precedence.

---

## Tier Definitions

### Tier 1 — Primary / Exchange Sources (Highest Trust)

| Source | Data Covered | Implementation | Notes |
|--------|-------------|----------------|-------|
| SEC EDGAR XBRL | Revenue, net income, EBITDA proxy (op. income + D&A), EPS (from income statement) | `reliability_lab/verifiers/sec_verifier.py` | No API key required. Free. Authoritative for US public companies. Uses `companyfacts` API. |
| Exchange / price feeds (yfinance) | Stock price, daily OHLCV, forward returns, SPY benchmark | `reliability_lab/verifiers/price_verifier.py` | Free. Near-real-time for prices. Authoritative for returns/alpha calculation. |

**When to use:** Revenue, historical earnings, price/return claims. Always prefer over Tier 3 when available.

**Limitations:**
- SEC EDGAR XBRL may lag filings by weeks
- Some concepts (EBITDA) require approximation (op. income + D&A) — see fact_table `source` field
- yfinance price data may have split adjustments; use `auto_adjust=True` (already set in code)

---

### Tier 2 — Company IR / Primary Disclosures (High Trust)

| Source | Data Covered | Implementation |
|--------|-------------|----------------|
| Earnings releases (8-K) | Quarterly/annual results, guidance | Not yet integrated |
| Earnings call transcripts | Management commentary, forward guidance | Not yet integrated |
| Investor day presentations | Multi-year targets, segment data | Not yet integrated |

**Status:** Not yet integrated. Planned for PR4 or later.

**When to use:** When SEC EDGAR XBRL doesn't have a specific metric (e.g. segment revenue, non-GAAP EBITDA), earnings releases are the next-best primary source.

---

### Tier 3 — Data Aggregators (Medium Trust)

| Source | Data Covered | Implementation | Notes |
|--------|-------------|----------------|-------|
| FMP free tier | EPS (netIncomePerShare), P/E, EV/EBITDA, gross/net margin, FCF, net income, total debt, market cap | `reliability_lab/verifiers/fmp_verifier.py` | 250 calls/day limit. 24h file cache. Uses `/stable/` endpoints. Revenue blocked on free tier — use SEC EDGAR. |

**When to use:** Valuation multiples, margin percentages, FCF — metrics not directly in SEC EDGAR XBRL.

**Limitations:**
- FMP is a data aggregator, not a primary source
- Free tier: limit=5 records per request (limit=6 silently returns 402)
- FMP P/E/EV-EBITDA are point-in-time (fiscal year end) — snapshot-date sensitive for valuations
- `ratios.enterpriseValueMultiple` and `key_metrics.evToEBITDA` may differ slightly

**Conflict rule:** If SEC EDGAR and FMP give different values for the same metric, SEC EDGAR wins. Record both values. If delta > tolerance, set `verification_status = SOURCE_CONFLICT` (PR3).

---

### Tier 4 — News and Analyst Commentary (Low Trust)

| Source | Example | Use |
|--------|---------|-----|
| Financial news (Bloomberg, Reuters, WSJ) | Earnings coverage, analyst upgrades | Not used for verification |
| Sell-side research notes | Price targets, estimates | Not used for verification |
| Reddit / social media | Retail sentiment | Not used for verification (available via reddit_utils.py, not used in audit) |

**When to use:** Never for primary verification. May be used as context for narrative claims or for the critic agent's background.

---

### Tier 5 — LLM-Generated Text (Lowest Trust — Object of Audit)

| Source | Description |
|--------|-------------|
| FinRobot HTML reports | Generated by Ollama Gemma4 12B MLX. This is the artifact being audited. |
| LLM claim extraction output | Claude/Gemma structured extraction of claims from Tier 5 text. One LLM output used to check another. |

**This is the thing being audited** — never use Tier 5 as a verification source for itself.

---

## Conflict Resolution Protocol

When two sources report different values for the same metric and period:

1. **Tier 1 vs. Tier 3 conflict:** Tier 1 (SEC/exchange) is canonical. Record both values.
2. **Delta ≤ tolerance:** Mark `verified` with the Tier 1 value. Note the Tier 3 value in `notes`.
3. **Delta > tolerance:** Mark `SOURCE_CONFLICT`. Do NOT mark as `incorrect`. Do NOT average.
4. **Both sources absent:** Mark `not_machine_verifiable`.

The `SOURCE_CONFLICT` status is planned for PR3 (disagreement layer). Until then, the first successful verifier's result is used.

---

## Tolerance Reference

| Metric Type | Tolerance | Rationale |
|-------------|-----------|-----------|
| Revenue (SEC EDGAR) | 2% | Accounting for rounding in LLM text |
| EPS (FMP) | 5% | Dilution adjustments vary |
| Valuation multiples (P/E, EV/EBITDA) | 10–15% | Point-in-time snapshot vs. fiscal year average |
| EBITDA proxy (op. income + D&A) | 15% | Approximation; true EBITDA includes more adjustments |
| Market cap | 20% | Current snapshot vs. historical; highly volatile |
| Margins (gross, net, EBITDA) | 10% | FMP decimal-to-percent conversion verified |
| Revenue growth (YoY %) | 10% | Requires two consecutive years of SEC data |

## Implementation Notes

- FMP API key: `config_api_keys` → `FMP_API_KEY`
- FMP cache: `reliability_lab/output/fmp_cache/` (24h TTL)
- Do NOT invalidate cache without good reason — costs 250 API calls/day to rebuild
- SEC EDGAR: no key required; rate-limit is soft (use reasonable delays for bulk runs)
- yfinance: no key required; `progress=False` and `auto_adjust=True` in all calls
